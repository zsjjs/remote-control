# ESP32 蓝牙继电器遥控器

本项目是 **`remote-control-app` 的 ESP32 接收端**。手机 App 可保存多台设备的名称和设备码，每次向**当前选中的设备**发送蓝牙广播开关指令。ESP32 根据**设备码**识别发给自己的指令并控制继电器；App 中该设备的设备码必须与接收端固件中的配置保持一致。

## 配合 remote-control-app 使用

以下操作使用 App 的中文界面名称，可在首页右上角的语言菜单切换中文 / English。首页底部的“配套固件源代码”可打开本项目仓库。

### 1. 先准备设备码

**配合本固件使用时，设备码就是 ESP32 固件中配置的 `kNetIdUuid`，也是蓝牙广播中的 iBeacon UUID。App 中当前设备的设备码与接收端必须使用同一个值。**

设备码应填写完整的 UUID，例如：

```text
12345678-1234-5678-9abc-def012345678
```

上面的值仅为示例。实际设备码可以通过以下方式获取：

- **使用已经部署好的设备**：向配置该设备的人获取设备码。
- **自己配置设备**：查看 `include/local_config.h` 中的 `kNetIdUuid`，引号内的完整字符串就是设备码。首次部署的配置和烧录步骤见后文。
- **查看已烧录设备的配置**：连接串口，在启动日志中找到 `Configured netId UUID: ...`，冒号后面就是该固件使用的设备码。

设备码在部署时配置，并随固件烧录到 ESP32。接收端只处理 UUID 匹配的广播。App 中的“设备名称”可自行命名，例如“家里车库”，用于区分列表中的设备，不参与广播匹配。

App 保存设备时只检查名称和设备码去除首尾空白后是否非空，保留设备码的字母大小写，**不在保存时校验 UUID 格式**。发送指令时才会将设备码转换为 UUID；因此保存成功并不代表可以控制接收端，配合本固件仍须填写有效且匹配的完整 UUID。

### 2. 在 App 中添加并选择设备

1. 完成 ESP32 接收端的接线和固件烧录，并给设备上电。
2. 首次使用时，首页显示“暂无设备”。点击“添加设备”进入“设备列表”，再点击右上角的“添加设备”（加号）。已有设备时，可从首页的“切换设备”或“选择设备”进入同一列表。
3. 填写“设备名称”和“设备码”：名称便于自己识别，设备码填写该接收端实际烧录的完整 UUID，然后点击“保存”。
4. 新增设备保存后会自动成为当前设备，编辑窗口关闭后仍停留在设备列表。点击设备条目返回首页，核对“当前设备”下显示的名称和设备码。
5. 打开手机蓝牙并允许 App 使用蓝牙，等待首页显示“蓝牙已就绪”。没有选中设备或蓝牙未就绪时，“开启”和“关闭”按钮不可用。
6. 保持 App 在前台，在接收端的蓝牙接收范围内点击“开启”或“关闭”。接收端匹配设备码后，触发对应继电器，输出约 **500 毫秒**的脉冲。

当前协议使用蓝牙广播，无需 Wi-Fi 或蓝牙配对，App 也不会扫描发现附近的接收端；设备需要手动添加。

### 3. 发送指令与广播规则

- 每次点击都使用当前选中设备的设备码生成 iBeacon 广播：“开启”对应 `major=1`，“关闭”对应 `major=2`，`minor` 为每次发送递增的 16 位指令编号。
- 每次广播持续 **1 秒**，随后自动停止。在这 1 秒内再次点击，会先停止旧广播，立即发送新指令，并从本次点击重新计时 1 秒。
- 打开设备列表、切换设备，或修改 / 删除当前设备时，会停止正在进行的广播。App 进入非活跃状态（如切到后台）或蓝牙变为不可用时，也会停止广播；回到前台或恢复蓝牙后需重新点击发送。
- 添加、保存、选择或删除设备都不会自动发送开关指令。这些操作只更新手机本地的设备资料和选择，不会修改接收端固件中的设备码。

接收端没有执行结果回执。App 显示“蓝牙已就绪”或“广播中”只表示手机端状态，是否执行成功仍以设备实际动作或串口日志为准。

连续操作时，应等待上一次硬件动作完成后再点击。App 会立即改发最新指令，但接收端在动作待执行或执行期间会忽略新指令且不排队；停止旧广播也不会撤销接收端已经接受的动作。接收端去重及重试规则见后文“重复广播与连续操作”。

### 4. 管理多台设备

- **切换设备**：从首页进入“设备列表”，点击目标设备条目即可选中并返回首页。后续点击“开启”或“关闭”时使用这台设备的设备码。
- **编辑设备**：点击设备条目右侧的省略号菜单，选择“编辑”，可修改名称和设备码。编辑已有设备会保留当前选择；修改当前设备的设备码后，下次发送使用新值。
- **删除设备**：在同一菜单中选择“删除”并确认。删除当前设备后会清空选择，不会自动选中其他设备；需手动选择剩余设备，或重新添加设备后才能发送。
- **本地保存**：设备列表和当前选择会保存在手机本地，重新打开 App 后恢复。
- **旧版升级**：从单设备版本升级时，已保存的设备码会一次性迁移为一条设备记录，初始名称使用原设备码，并自动选中；之后可通过“编辑”改为易识别的名称。

### 5. 设备码相关问题

| 问题 | 说明 |
| --- | --- |
| 设备码填什么？ | 填接收端固件中 `kNetIdUuid` 的完整 UUID，保留连字符，十六进制字母大小写均可 |
| 能保存设备，但点击时提示“无法为该设备码生成蓝牙广播” | 保存时只检查必填项，发送时才转换 UUID；请编辑设备，将设备码改为接收端实际使用的完整 UUID |
| 配置设备码后，设备没有响应 | 先核对首页“当前设备”及其设备码，确认与目标接收端实际烧录的 UUID 一致；只修改本地配置文件而没有重新烧录，不会改变设备码。再检查设备供电、蓝牙权限、App 是否保持前台及距离 |
| 删除设备后，“开启”和“关闭”按钮不可用 | 删除当前设备会清空选择；进入设备列表重新选择其他设备，或添加新设备，同时确认蓝牙已就绪 |
| 如何更换接收端的设备码？ | 修改 `include/local_config.h` 中的 `kNetIdUuid`，重新编译烧录，并让 App 使用新的设备码。仅修改 App 中的设备码不会更改接收端配置 |
| 多台接收端用了同一设备码会怎样？ | 广播范围内所有匹配设备码的接收端都可能响应；需要分别控制时，应为各设备配置不同 UUID |

## 硬件部署与开发参考

以下内容用于首次部署硬件、重新烧录或排查问题。

固件基于 **ESP32 + Arduino + PlatformIO**。ESP32 持续被动扫描 iBeacon 广播，匹配配置的 UUID（`netId`），再根据广播中的 `major` 值触发“开”或“关”继电器。每次触发输出约 500 毫秒的低电平脉冲，随后恢复高电平，不会持续保持继电器吸合。

### 1. 准备硬件与开发环境

- ESP32 开发板：当前 PlatformIO 配置为 `esp32dev`。
- USB 数据线，用于供电、烧录和查看串口日志。
- 两路低电平触发、输入兼容 ESP32 3.3V 逻辑的继电器模块。
- 安装了 `remote-control-app` 的 iPhone；协议调试时也可使用支持自定义 UUID、major、minor 的 iBeacon 广播工具或 BLE 发送设备。
- 开发环境：推荐使用 VS Code 和 [PlatformIO IDE 扩展](https://platformio.org/install/ide?install=vscode)，也可以安装 [PlatformIO Core](https://docs.platformio.org/en/latest/core/installation/index.html) 使用命令行。

安装后用 VS Code 打开项目根目录。下文命令均在项目根目录执行；使用扩展时可以在 PlatformIO Core CLI 终端中运行 `pio` 命令。

### 2. 硬件接线

| ESP32 引脚 | 连接位置 | 作用 |
| --- | --- | --- |
| GPIO25 | “开”继电器的控制输入，如 IN1 | 收到开指令时拉低约 500 毫秒 |
| GPIO26 | “关”继电器的控制输入，如 IN2 | 收到关指令时拉低约 500 毫秒 |
| GND | 继电器模块的控制侧 GND | 常规非隔离接法下共地 |

继电器模块按其额定电压供电，GPIO 只连接兼容的控制输入，不直接驱动继电器线圈或负载。继电器触点如何连接被控设备，应按该设备的控制接口确定；当前程序提供的是短按式“开 / 关”信号。

默认空闲电平为 `HIGH`，有效电平为 `LOW`。两路输出按互斥方式工作，执行一次脉冲时不会同时触发另一通道。

### 3. 配置接收端 UUID（设备码）

首次使用时，从模板创建本地配置文件；如果已经存在 `include/local_config.h`，直接编辑该文件即可。

```bash
cp include/local_config.example.h include/local_config.h
```

在 `include/local_config.h` 中设置自己的 `kNetIdUuid`。这个值就是稍后要填入 `remote-control-app` 的设备码，例如：

```cpp
#pragma once

constexpr char kNetIdUuid[] = "12345678-1234-5678-9abc-def012345678";
```

- UUID 必须采用 `8-4-4-4-12` 格式，共 36 个字符，十六进制字母大小写均可。
- `remote-control-app` 使用的设备码必须与这里一致；上面的值仅用于演示，应替换为自己的 UUID。
- `include/local_config.h` 已加入 `.gitignore`，无需提交个人配置。
- UUID 会编译进固件，修改后需要重新编译和烧录。

UUID 只用于筛选广播，当前协议没有身份认证或加密。

### 4. 选择串口、编译和烧录

连接 ESP32 后，查看串口设备：

```bash
pio device list
```

编辑 `platformio.ini`，将 `upload_port` 和 `monitor_port` 改为设备列表中的实际串口。仓库当前的配置如下，其中的串口路径需要按自己的电脑调整：

```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
upload_port = /dev/tty.usbserial-A5069RR4
monitor_port = /dev/tty.usbserial-A5069RR4
monitor_speed = 115200
```

macOS 串口通常类似 `/dev/cu.usbserial-xxxx`，Linux 类似 `/dev/ttyUSB0`，Windows 类似 `COM3`，以实际设备列表为准。

编译固件：

```bash
pio run -e esp32dev
```

首次编译时，PlatformIO 会下载所需平台、工具链和 Arduino 框架，需要网络连接。

烧录到开发板：

```bash
pio run -e esp32dev -t upload
```

打开串口监视器：

```bash
pio device monitor -b 115200
```

按 `Ctrl+C` 退出监视器。再次烧录前先退出，避免占用串口。也可以在 VS Code 的 PlatformIO 面板中选择 `esp32dev` 环境，依次使用 Build、Upload 和 Monitor。

打开监视器后如需查看完整启动日志，按开发板的复位键。正常启动时可以看到类似输出：

```text
Booting BLE beacon relay scanner...
Configured netId UUID: 12345678-1234-5678-9abc-def012345678
Command mapping: major 1=open, major 2=close
Scan window=100ms, scan interval=100ms, duplicate ignore=3500ms
BLE passive scan started
```

### 5. 调试：手动发送“开 / 关”指令

日常使用由 `remote-control-app` 发送开关指令。以下步骤仅用于通过其他工具调试接收端协议。

在调试工具中选择 **iBeacon 广播模式**，配置以下字段：

| 字段 | 填写方式 |
| --- | --- |
| UUID | 与 `include/local_config.h` 中的 `kNetIdUuid` 一致 |
| major | `1` 表示开，`2` 表示关；其他值会被忽略 |
| minor | `0`～`65535`，作为指令编号；建议每次新操作更换编号 |
| Tx Power | 按发送工具要求填写，接收端不使用该字段判断动作 |

一次完整的操作示例：

1. 设置匹配的 UUID、`major=1`、`minor=1`，短暂开启广播，例如约 1 秒后停止。
2. 接收端匹配后，GPIO25 输出约 500 毫秒的低电平脉冲，串口打印开指令日志。
3. 等待该脉冲结束后，设置 `major=2`、`minor=2`，再次短暂广播并停止。
4. GPIO26 输出约 500 毫秒的低电平脉冲，串口打印关指令日志。

开指令的日志示例（RSSI 随距离和环境变化）：

```text
Accepted beacon: netId=12345678-1234-5678-9abc-def012345678 major=1 minor=1 action=open rssi=-60
Executing open pulse on GPIO25
Open pulse complete
```

关指令对应 `action=close`、`Executing close pulse on GPIO26` 和 `Close pulse complete`。目前没有发送端确认回包，是否接收成功需要通过接收端日志和实际硬件动作判断。

#### 重复广播与连续操作

- 接收端用 `(major, minor)` 判断重复指令，最多保存 4 条近期记录。记录保留期间，同一组合在记录后的 3500 毫秒内不会再次执行。
- 去重窗口不是永久限制：同一广播持续发送超过窗口后，仍可能再次触发。因此一次操作结束后应停止广播。
- 继电器有待执行或正在执行的动作时，新指令会直接被忽略，不会排队。忙碌时被忽略的指令也会进入去重记录；重试时应等待空闲并使用新的 `minor`，或等待原记录的去重窗口结束。
- 判断依据是 UUID、major 和 minor，不限制发送设备地址，也不使用 RSSI 作为触发距离阈值。

#### 自行实现发送端时的广播格式

接收端要求 Manufacturer Data **恰好为 25 字节**，以下长度包含两字节 Company ID，不包含外层 BLE AD 的长度和类型字段：

```text
4C 00 | 02 15 | UUID（16 字节）| major（2 字节）| minor（2 字节）| Tx Power（1 字节）
```

- Company ID 为 `0x004C`，在线数据中的顺序为 `4C 00`；后续 iBeacon 标识为 `02 15`。
- UUID 按标准文本去掉连字符后的字节顺序发送，major 和 minor 均使用大端序。例如 major 为 1 时编码为 `00 01`。
- 如果发送工具把 Company ID 单独作为参数，请填 `0x004C`，其余数据从 `02 15` 开始，避免重复添加 Company ID。
- 接收端使用被动扫描，iBeacon 数据需要放在广播包中，不能只放在需要主动扫描才能获取的 Scan Response 中。

### 6. 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 编译提示找不到 `local_config.h` | 按“配置接收端 UUID（设备码）”一节复制模板，确认文件位于 `include/local_config.h` |
| 提示 `pio: command not found` | 使用 PlatformIO Core CLI 终端，或安装 PlatformIO Core 并配置 PATH |
| 上传失败或找不到串口 | 用 `pio device list` 确认端口，检查 USB 数据线、驱动和串口占用；部分开发板烧录时需要按住 BOOT 键 |
| 串口乱码 | 确认监视器波特率为 `115200` |
| `Invalid netId UUID in local_config.h` | 检查 UUID 的长度、连字符位置及十六进制字符，修正后重新烧录 |
| `BLE passive scan failed to start` | 程序会约每 1 秒重试；若持续失败，检查供电并复位设备，观察后续日志 |
| 广播后没有动作，也没有指令日志 | 确认发送端正在发送 iBeacon、UUID 一致、广播格式正确，且数据位于广播包中；不匹配的广播和重复指令会静默忽略 |
| `unsupported major` | 发送端 major 只使用 `1` 或 `2` |
| `Ignoring beacon while relay busy` | 等待当前动作结束后，使用新的 minor 重试 |
| 同一指令反复触发 | 检查发送端是否持续广播；每次操作后停止广播 |
| 日志显示执行成功，但继电器没有动作 | 检查 GPIO25 / GPIO26 接线、模块供电、控制侧共地及低电平触发兼容性；日志只表示引脚脉冲已执行，没有继电器或负载状态反馈 |

### 7. 文件与可调整参数

| 文件 | 用途 |
| --- | --- |
| `src/main.cpp` | iBeacon 解析、指令去重、BLE 扫描和继电器控制 |
| `include/local_config.example.h` | UUID 配置模板 |

需要调整硬件或动作时序时，可修改 `src/main.cpp` 顶部的常量并重新烧录：

| 常量 | 默认值 | 含义 |
| --- | --- | --- |
| `kPinOpen` / `kPinClose` | `25` / `26` | 开 / 关输出引脚 |
| `kRelayActiveLevel` / `kRelayIdleLevel` | `LOW` / `HIGH` | 继电器有效 / 空闲电平 |
| `kRelayPulseMs` | `500` | 输出脉冲时长，单位毫秒 |
| `kDuplicateIgnoreMs` | `3500` | 重复指令忽略窗口，单位毫秒 |
| `kScanIntervalMs` / `kScanWindowMs` | `100` / `100` | BLE 扫描间隔 / 窗口，单位毫秒 |
| `kMajorOpen` / `kMajorClose` | `1` / `2` | 开 / 关指令的 major 值 |
